AI-GIS Dashboard payload test list
=================================

How to use:
- Paste one payload at a time into the /tester page.
- The app checks stacked_proba >= 0.5.
- If true -> verdict = MALICIOUS
- If false -> verdict = benign

General expected behavior:
- SQLi and XSS payloads should usually come back as MALICIOUS.
- Benign-looking text with quotes, SQL-like words, code fragments, or punctuation may be scored as benign, but can sometimes trigger false positives if they appear "malicious-like".
- Polymorphic payloads are designed to look obfuscated, mutated, or encoded while still being malicious.

SECTION 4: Mixed / deceptive benigns that look malicious
--------------------------------------------------------
These are the best tests for false positives.

41) "SELECT * FROM users WHERE id = 1; -- business data export script"
    Expected: usually benign, but may trigger suspicion because of SQL wording

42) "Error code: 500 (Internal Server Error) -- SQL injection test not reproduced"
    Expected: benign*

43) "The SQL statement: SELECT is a keyword, not an attack."
    Expected: benign

44) "Demo payload: <script> example only, not executable code in prod "
    Expected: benign, but could be close to a false positive

45) "customer note: alert(1) appears in pricing example, not in browser code"
    Expected: benign

46) "<img> tag used in a HTML tutorial snippet, not actual active XSS"
    Expected: benign

47) "script = 'not a real exploit'; if (flag) { alert('demo'); }"
    Expected: benign

48) "This product has a user id='123' and a price > 50; not a vulnerability"
    Expected: benign

49) "Review the query: SELECT * FROM orders WHERE status='open'; not malicious context"
    Expected: benign

50) "Example code snippet: <svg onload=alert(1)> for documentation only"
    Expected: benign, but a risky near-miss for naive models

Quick summary:
- If it contains SQLi/XSS semantics with quotes, operators, or script tags -> MALICIOUS
- If it merely mentions SQL, JS, or code-like snippets without being executable -> usually benign
- If it is heavily obfuscated or encoded but still contains attack structure -> MALICIOUS

Model threshold from app code:
- verdict = "MALICIOUS" if stacked_proba >= 0.5
- verdict = "benign" otherwise
