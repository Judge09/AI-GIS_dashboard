AI-GIS: everything that happened

Every script, every fix, every result — from raw traffic data to a working stacked detection system. This is the whole story in one place.

1The goal

What AI-GIS is trying to prove

Build a detection system that combines a Random Forest and an LSTM — blended by a trained meta-learner — and show it detects SQL injection and XSS attacks better than the old rule-based standard, ModSecurity + OWASP CRS. The hardest part of that claim: proving it holds up against attacks written by an LLM specifically to evade detection — not just attacks the model has already seen the shape of.

The starting point — WEB-IDS23 — only contains flow-level statistics (packet counts, timing, TCP flags). It never included raw HTTP payload text at all. 3Building the dataset — the real story

This took 6 versions to get right. Here's what broke and what fixed it.

v1-v3First working converter
CSV → honeypot log, basic payload templates. Worked, but only ~30 unique attack strings total.
v4Discovered: 72.9% of ALL rows were exact duplicates
Fixed row counts and balance looked right, but the actual payload content repeated constantly — some XSS strings appeared 30-39 times. This would have leaked across train/val/test and inflated every metric.
v5Combinatorial payload generators
Replaced fixed strings with generators that compose payloads from randomized components (table names, delays, quote styles, JS actions). Attack-side duplication: 0%. Also fixed: synthetic public IPs (was leaking internal lab IPs), realistic session clustering.
v5Benign traffic still 100% duplicated
Only 128 distinct benign values, appearing in all three splits — session grouping doesn't stop identical content from crossing train/val/test.
v6Same generator treatment applied to benign
18,182 distinct benign values — matches row count exactly. Added an automated cross-split payload-overlap check so this class of bug can't silently return.
v6Sessions read as random noise, not real visits
A "session" would jump categories every request and once used an email address as a search query. Not coherent.
v7Session archetypes + shared identity
Each session now picks one persona (same email, same product interest) and a plausible path sequence. Found + fixed a real bug along the way: pagination always started at page 1, guaranteeing collisions across sessions.
v7Character-set tell: benign text had zero uppercase, zero spaces
SQL keywords are uppercase; benign text was all-lowercase by construction. A model could "detect attacks" just by checking for a capital letter — meaningless signal.
v8-v9Hard-negative benign phrases
Added realistic business/technical text with apostrophes, semicolons, ampersands, parens — the same characters attacks use, in legitimate context. 34 phrases, ~55% of benign sessions.

Random Forest — two versions

VersionFeatures
v1 (original)11 raw counts: payload length, entropy, special-char count, digit count, uppercase count, quote count, comment-token count, keyword flags, etc.
v2 (improved)Same 11 + 8 structural pattern features (tautology detection "X=X", quote-before-SQL-keyword, HTML tag opening, event-handler pattern, longest punctuation run, special-char ratio not raw count) + 300 character n-gram TF-IDF features

v1 only counted symbols — it couldn't tell "a semicolon in a sentence" from "a semicolon in 1; DROP TABLE users." v2 looks at the actual shape of the text instead.

LSTM — exact architecture

Embedding(128 → 32, mask_zero=True)
→ LSTM(64, return_sequences=True)
→ Dropout(0.3)
→ LSTM(32)
→ Dropout(0.3)
→ Dense(1, sigmoid)

Unidirectional — matches your confirmed spec exactly, not Bidirectional. Found and fixed a real bug: mask_zero=True was missing at first, so the model tried to learn from ~160 padding characters after every short payload. Without it, the model didn't learn anything at all (stuck at 50% accuracy). With it: 98-99% accuracy within 1 epoch.

Meta-learner

Logistic Regression, trained on [rf_probability, lstm_probability] from the validation set — not train, to avoid the base models grading their own homework. This matches your spec exactly: a trained combiner, not a hardcoded weighted average.

5The training & testing journey

Why "100% accuracy" turned out to be a warning sign, not a win

Step 1 — Clean test set: AUC-ROC 1.000, everywhere. Every version, every model, perfect scores. This should have been a red flag, not a celebration.

Step 2 — Built a stress test. 23 hand-written "evasion-style" attacks (hex-encoded, whitespace tricks, split keywords) + 15 ordinary sentences a real website sees ("Smith & Sons Law Firm", error messages, code snippets).

Step 3 — The real result: 80% false-positive rate. The RF was flagging normal business text as attacks 4 times out of 5. Root cause, measured directly: one feature (num_special_chars) was 40% of its decision-making. It had learned "lots of symbols = bad," not actual attack structure.

Step 4 — Same problem, worse, at the character level. Checked the LSTM's raw input: every uppercase letter and every space character appeared only in attack payloads, never in benign. A trivial shortcut was sitting right there in the data.

Step 5 — Fixed it in layers: hard-negative benign phrases (symbol-rich but legitimate text) → structural RF features → properly-trained LSTM with checkpointing → the meta-learner combining both. Each layer measured, not assumed.

Bottom line

A full, working, honestly-tested pipeline exists — from raw traffic data to a stacked detection system that catches real attacks and mostly leaves normal traffic alone. Every bug along the way was found by testing, not assumed away, and every fix was measured before being trusted. What's left isn't more engineering on this system — it's plugging in the real evasion payloads and the ModSecurity baseline, which is what turns this from "a working system" into "a thesis result."
