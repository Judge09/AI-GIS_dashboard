Pipeline Overview

This pipeline turns WEB-IDS23 flow-level CSVs (ground-truth labels, no payload text) into labeled, leakage-free training data for both base learners in the confirmed architecture: Random Forest (engineered features) and the plain unidirectional stacked LSTM (character sequence).

Two-stage flow

prepare_honeypot_for_training.py
→
Output
RF/LSTM train-val-test tensors
Methodological note — must appear in Chapter 3 disclosure WEB-IDS23 provides flow-level metadata and ground-truth labels only, not raw payload text. Payload content is synthetically generated per flow using documented, parameterized attack-pattern generators. Source/destination IPs are also synthetic. Disclose this the same way Resecurity telemetry is disclosed — as synthetically generated, not raw captured logs.

Why this design

  • Combinatorial generation, not a fixed bank: earlier versions drew from ~14 SQLi / ~14 XSS literal strings — a model trained on that mostly memorizes strings instead of learning structure. v4 composes payloads from components across 7 SQLi + 3 XSS families, yielding tens of thousands of distinct strings.
  • Session-grouped splitting (by session_id, not row) prevents the model from learning session-level artifacts instead of payload structure.
  • SMOTE on RF train split only, after the split is finalized — matches the confirmed leakage-prevention rule.

03

Stage 1 — Generate the Honeypot Log

webids23_to_honeypot_log_v4.py

What it does internally

  • Counts natural row counts per CSV, computes SQLi/XSS/benign targets per --strategy.
  • Reservoir-samples flows up to target count (memory-safe streaming).
  • Per attack flow: uniformly selects an attack family, calls that family's combinatorial generator.
  • With probability --obfuscate-prob: applies WAF-evasion obfuscation (case randomization, whitespace→comment, URL-encoding).
  • Groups requests into synthetic sessions via 120-second time buckets per source IP; assigns synthetic public IP + consistent user-agent.
  • Writes one JSON object per line with full request/session/label metadata.
  • Prints a distribution report: totals, label balance, family breakdown, distinct payload strings, duplicate %.
SQLi families (7)XSS families (3)
tautology, union_based, time_based_blind, boolean_blind, error_based, stacked_query, auth_bypassreflected, stored, dom_based

Command

--strategyEffect
match_minSQLi/XSS targets both = min(natural counts). Recommended default.
match_maxBoth = max(...) — heavy synthetic duplication of the smaller class.
customSet --custom-sqli-count / --custom-xss-count explicitly.
python3 webids23_to_honeypot_log_v4.py \
  --sqli-http   webids23_sqli_http.csv \
  --sqli-https  webids23_sqli_https.csv \
  --xss-http    webids23_xss_http.csv \
  --xss-https   webids23_xss_https.csv \
  --benign      webids23_benign.csv \
  --strategy match_min \
  --benign-ratio 1.0 \
  --obfuscate-prob 0.4 \
  --seed 42 \
  -o honeypot_from_webids23.log

04

Stage 2 — Prepare Training Data

prepare_honeypot_for_training.py

What it does internally

  • Loads JSONL, reconstructs payload text (query + body), engineers 11 RF features (length, entropy, special-char/digit/uppercase counts, param count, POST flag, SQLi/XSS keyword flags, quote count, comment-token count).
  • Splits by session_id via GroupShuffleSplit — 70/15/15, no session crosses a boundary.
  • If --smote: fits on the RF train split only, after split is finalized. Never touches LSTM sequences. Synthetic rows marked _session_id = "SMOTE_SYNTHETIC".
  • Ordinal-encodes payload text for LSTM: ASCII 0–127, 0=PAD, 1=UNK, fixed length max_payload_len (default 200).
  • Writes lstm_{train,val,test}.npz, rf_{train,val,test}.csv, split_manifest.json.
Naming note — from prior adviser feedback The parameter is --max-payload-len throughout, corrected from the original sequence_len bug (which collided session windowing with payload character tokenization). Keep this name consistent downstream.

Command

python3 prepare_honeypot_for_training.py \
  --input honeypot_from_webids23.log \
  --outdir prepared_data \
  --max-payload-len 200 \
  --seed 42 \
  --smote

Omit --smote to leave RF train at natural balance — e.g. for the ablation study's non-SMOTE condition.

7.2 Interface contracts

RF and LSTM trainers

  • Input: the exact Stage 2 files, no reshaping/re-encoding inside the trainer.
  • Output: predicted probabilities on the validation split specifically — the meta-learner trains on these, not train-split predictions.

Meta-learner

  • Input: RF + LSTM validation-set probabilities, row-aligned.
  • Must be a trained Logistic Regression — not a fixed weighted average. This is the exact mismatch flagged in §8; do not substitute a hardcoded blend even as a placeholder.
  • Output: combined probability + threshold chosen on validation data before test exposure.

AI-GIS vs. ModSecurity — the comparison point

  • Both systems run independently on the SAME frozen held-out set — neither sees the other's output first.
  • Same output shape: one row per request, binary decision + continuous score.
  • Evaluation script (bootstrap CI, McNemar's, F1/FPR/AUC-ROC) ties both together by request ID, agnostic to how each score was produced.

8.4 Replacing the Dataset Pipeline

The current system treats "which dataset" as an open choice. Per the confirmed methodology this needs to become a fixed pipeline: WEB-IDS23 → combinatorial generator → prepared tensors, with Resecurity as primary once access is confirmed.

Flag — three different RF feature schemas are now in play (1) This doc's Stage 2 output: 11 columns (payload_len, entropy, num_special_chars, num_digits, num_uppercase, param_count, is_post, has_sqli_keyword, has_xss_keyword, quote_count, comment_token_count). (2) Current system's built-in engineering: 8 columns (url_score, payload_len, entropy, req_freq, method_score, param_count, path_depth, header_score). (3) Table 11's target: 30 dimensions. These are NOT the same features under different names — req_freq/header_score don't exist in Stage 2's output; has_sqli_keyword/has_xss_keyword don't exist in the system's extractor. Decide explicitly whether Stage 2's engineering replaces the system's extractor or both merge into the full 30-dim set, before wiring rf_train.csv into the RF trainer. Silently swapping the CSV either breaks the trainer (column mismatch) or silently trains on the wrong definition — raise this with your adviser if unclear.
